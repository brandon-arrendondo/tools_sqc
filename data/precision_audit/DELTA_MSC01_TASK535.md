## This is overwhelmingly codebase-idiom noise, not one checker bug

Unlike MSC17-C (task 534, a single structural gap dominating the FPs),
MSC01-C's 1,328 FPs are a genuinely diverse mix of idioms the rule's
"if/else-if with no final else = unhandled case" heuristic cannot see
structurally:

1. **Pre-initialized default / already-correct fallback value** — a variable
   set to a sane default before the chain, so an unmatched condition
   correctly leaves it unchanged (dominant in sqlite: `rc=SQLITE_OK`,
   flags left at their initialized state, clamp idioms where "in range"
   needs no adjustment).
2. **"Log-selector before unconditional cleanup/return" pattern** — the
   chain only picks *which* diagnostic message to print or *which* known
   sub-case to handle specially; an unconditional statement immediately
   after the chain (`return rc;`, a shared cleanup path) already handles
   every value regardless of which (if any) branch fired. Dominant in
   mosquitto's `src/bridge.c` and much of curl (state-machine polling code:
   "not done yet, revisit next poll" is the correct no-op).
3. **Exhaustive-in-practice dispatch** — an enum/opcode/type-constant
   dispatch that is provably exhaustive over the actual value domain
   (validated earlier by an assert, a parser, or the bytecode loader), so
   there is no reachable unhandled case. Common across all 6 projects,
   especially Lua's VM/opcode code (100% FP — CLAUDE.md's structural-C99
   /"invariant-heavy" character of raylib and Lua's VM code held here too).
4. **Independent optional-condition chain, not real dispatch** — a sequence
   of unrelated flag/mode checks where "none matched" is correctly
   "nothing extra to do," not an unhandled case in CERT's intended sense.
5. **Two-sided clamp idiom** (`if(x<min) ... else if(x>max) ...`) — the
   omitted else is "already in range," the correct no-op. Very common in
   raylib (audio pan/volume clamps, window state clamps).

## Real bugs found (28 TP)

Unlike MSC17-C, the TPs here are a genuinely diverse set of real,
independent unhandled-case defects, not one structural class:

- **raylib (18 TP, dominant cluster)** — mostly platform-backend event/input
  dispatch gaps: `TOUCH_ACTION_CANCEL` never handled (rgestures.h ×2,
  rcore_web.c, rcore_web_emscripten.c — touch/gesture state left stuck),
  Android motion-event type dispatch falling through into type-unsafe
  code (`rcore_android.c:1270`), mouse-button remapping collision
  (`rcore_desktop_rgfw.c:645`, Misc1 aliases onto Middle), several
  "silent success with unset output" bugs (`rmodels.c:6451` GLTF pose
  interpolation returns `true` without writing `*data`; `rtext.c:910`
  `GenImageFontAtlas` returns uninitialized `recs` for an unrecognized
  `packMethod`), and format-dispatch gaps (WAV 8-bit PCM never refilled,
  ASTC 8x8 block-size under-allocation, cubemap layout leaving `width=0`
  silently).
- **mosquitto (6 TP)** — `bridge.c:992` (non-ECONNREFUSED pending-connect
  errors leave the bridge stuck), `conf.c:1047` (unrecognized MQTT
  protocol-version tokens silently accepted), `handle_subscribe.c:201`
  (mqtt31 SUBACK omitted from the ACL-denied failure path),
  `listeners.c:298` (`mqtt-sn` listener type never actually started),
  `plugin_public.c:737` (`mosq_bmd_all` direction never clears outgoing
  messages), `websockets.c:415` (uncovered `realpath()` errno sends no
  HTTP response at all).
- **curl (3 TP)** — `http.c:2615` (POST_FORM/POST_MIME skip the
  Range-header dispatch), `setopt.c:2562` (malformed `CURLOPT_ECH` string
  silently accepted), `tool_operate.c:735` (Windows-only upload-fd leak).
- **hostap (1 TP)** — `wpa_auth_ft.c:3040`: `WPA_KEY_MGMT_FT_SAE`/
  `FT_SAE_EXT_KEY` unhandled in the FT AKM dispatch, leaving
  `sm->wpa_key_mgmt` silently unset while the function returns success.
- **sqlite, lua (0 TP each)** — every sqlite and lua finding in this batch
  was FP; both codebases' heavy reliance on pre-established invariants
  (bounded enums validated earlier, pre-initialized defaults) makes
  MSC01-C's heuristic maximally noisy there, consistent with the
  memory note on Lua's VM/opcode dispatch relying on prior validation.

## Follow-up

No single rule-logic fix is indicated here (contrast MSC17-C task 534's
one dominant structural gap) — the FP causes are genuinely heterogeneous
codebase idioms. The 28 confirmed TPs are real, independent bugs in their
respective upstream projects; none currently blocks a sqc rule-logic
change. Given 0% precision on sqlite/lua specifically, a future narrow
improvement worth scoping separately: recognizing the "unconditional
statement/return immediately follows the if/else-if chain" pattern
(cause #2 above) as exhaustive, which alone would kill a large fraction
of the mosquitto/curl FPs without touching the genuinely-exhaustive-enum
cases that already need real type-domain reasoning.
