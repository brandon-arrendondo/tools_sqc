## This is a rule bug, not codebase noise

Unlike prior delta passes (MEM31-C task 420: real ownership-heuristic FPs
spread across many independent causes), **this delta is dominated by one
structural gap in MSC17-C's own checker** (`src/rules/cert_c/MSC/MSC17-C/
msc17_c.rs`), confirmed independently by every batch across all 5 projects:

1. **Braced case-body blocks** (`case X: { ...; break; }`) — by far the
   largest cause (well over 1,000 of the 1,441 FPs). `case_body_items()`
   collects the case section's top-level children; when the whole body is
   one `compound_statement` node, `terminates_section()` checks *that
   node's own kind* (`compound_statement`), never recursing inside to find
   the real trailing `break`/`return`/`continue`/`goto`. sqlite, lua, and
   much of curl/mosquitto wrap virtually every case body this way, so this
   single gap explains the overwhelming majority of findings in 4 of 5
   projects.
2. **`if`/`else` (or nested-switch) branches that all terminate** — same
   root cause, one level of nesting different: the case body's last
   top-level statement is an `if_statement` whose every arm ends in
   break/return, but the checker only inspects the `if_statement` node's
   own kind. Seen in mosquitto (`lib/options.c`), lua (`lcorolib.c`), curl
   (`curl_gssapi.c`, `curl_sasl.c`, `progress.c`, `setopt.c`).
3. **Non-comment intentional-fallthrough markers** — `is_fallthrough_comment()`
   only recognizes a trailing `comment` node containing "fall"; it misses:
   - curl's `FALLTHROUGH()` macro (`__attribute__((fallthrough))`) — the
     single largest FP driver in curl, dozens of sites.
   - sqlite's `deliberate_fall_through` marker statement (bare identifier,
     not a comment) — dozens of sites, several paired with an actual
     "fall through" comment that isn't the section's *last* item (a
     marker statement follows it), so `items.last()` never sees the
     comment.
   - a C23/GNU `__attribute__((fallthrough))`/`[[fallthrough]]` attribute
     statement generally (not a `comment` AST node at all).
4. **Preprocessor-adjacent case boundaries** — when a `#if`/`#ifdef` block
   sits directly between a terminated case body and the next `case` label,
   the checker appears to misjudge the section boundary and reports a
   fallthrough that isn't there. Seen repeatedly in mosquitto (8/15 of its
   batch) and raylib (7/8 FPs), and a few curl sites.
5. **Empty/stacked grouped case labels** (`case A: case B: { ...; break; }`)
   — already exempted by the rule's own empty-section check, but the
   *following* label's braced body still hits bug #1, so the group as a
   whole still misfires.

The 25 genuine TPs are concentrated in:
- `ext/rtree/rtree.c` (sqlite, 16 TP) — two intentionally-cascading
  coordinate/volume-accumulator switches (`rtreeCallbackConstraint`,
  `cellArea`) with no comment/marker at all. Per sqc's surface-the-letter-
  of-the-rule philosophy, these are correctly TP: the code's cascading
  intent doesn't change that CERT requires a marker and there isn't one.
- `ext/rbu/sqlite3rbu.c`, `ext/recover/dbdata.c`, `ext/misc/zipfile.c`
  (sqlite, 8 TP) — genuine unmarked numeric/checksum fallthrough chains.
- `src/rcore_desktop_win32.c:1950` (raylib, 1 TP) — real unmarked
  `WM_PAINT`→`WM_INPUT` fallthrough, no preprocessor involvement.

## Follow-up

Filed as a new rule-fix task (see `todo-sqlite-cli`): MSC17-C needs to (a)
recurse into a case body's trailing `compound_statement`/`if_statement`
to find the true terminating statement instead of checking only the
outermost node's kind, and (b) recognize non-comment intentional-fallthrough
markers (`FALLTHROUGH()`/`__attribute__((fallthrough))`/`[[fallthrough]]`
attribute statements, and marker identifiers like `deliberate_fall_through`
that follow rather than are the section's last comment). Given the
measured 1.5% precision here is overwhelmingly a checker-logic problem
rather than a codebase-convention problem, fixing this should be high-
leverage: on this evidence alone it could plausibly flip a majority of the
1,441 FPs to true negatives.
