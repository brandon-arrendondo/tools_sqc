## Zero TPs, but the FP causes cluster into fixable analyzer gaps

Unlike a diffuse "codebase idiom" pattern (MSC01-C, task 535), this batch's
FPs concentrate into a small number of structural gaps in ARR30-C's own
bounds-tracking, recurring independently across projects:

1. **Flexible array members read at declared size, not real allocation**
   (dominant in sqlite, seen in 2 of 3 independent sqlite batches) — C99
   struct-hack fields declared `T a[1]` or `T a[FLEXARRAY]` are actually
   malloc'd via a `sizeof(struct)+n*sizeof(T)`-style macro to hold the real
   element count (`nSeg`, `nTask`, `nSegment`, `nTerm`, …), and every access
   is correctly bounded by that count — but the checker appears to read the
   *declared* array size rather than the real allocation size.
2. **Loop-counter/allocation-size correlation lost** — an index bounded by
   a loop (`for(i=0;i<pIter->nSeg;i++) ... pIter->aSeg[i]`) where the loop
   bound and the array's real size come from the same field; sqc's static
   bound-tracking loses this correlation for FTS5/FTS3 index-merge code in
   particular.
3. **Hash/modulo-bounded indices** — `h % HASHSIZE`, `PMKID_HASH`,
   `% NAN_DE_MAX_SERVICE`-style indices that are mathematically guaranteed
   in range but not recognized as such.
4. **Third-party macro `sizeof()` blindness** — all 11 curl mbedTLS
   findings are the identical `mbedtls_strerror(ret, errorbuf,
   sizeof(errorbuf))` call, correctly passing the real 128-byte buffer's
   `sizeof()`; flagged only because sqc can't expand the third-party macro.
5. **NUL-terminated string/UTF-8 traversal** (`while(*p)`, continuation-byte
   skips) flagged as "unbounded" despite being guaranteed-terminated,
   standard C idioms — no fixed array to overrun.
6. **A genuine analyzer buffer mis-linking bug** (not a classification
   issue) — hostap's `p2p_supplicant.c:5132` finding pointed at a real
   256-byte stack array but sqc had linked the bounds-check to an unrelated
   struct's flexible-array member from a different function entirely.
7. **Enum-closed dispatch** — index parameters that are always literal
   compile-time constants from a closed enum at every call site, not
   attacker-controlled.

## Follow-up

Two concrete, independently-corroborated analyzer-gap candidates worth
scoping as their own rule-fix tasks (not filed yet — flagging here per
CLAUDE.md's delta-adjudication protocol for surfacing checker bugs found
during adjudication):

- **Flexible-array-member real-size resolution** (#1 above): ARR30-C
  (and likely other bounds rules sharing the same size-resolution helper)
  should resolve a flexible-array-member's real element count from its
  allocation site (`sizeof(struct)+n*sizeof(elem)` idiom) instead of its
  declared size. Recurred independently in 2 of 3 sqlite batches — high
  confidence this is systematic, not project-specific.
- **hostap `p2p_supplicant.c:5132` buffer mis-linking** (#6 above): a real
  analyzer correctness bug (wrong buffer attributed to a bounds check),
  distinct from an FP-tuning issue — worth a standalone repro/fix task.
